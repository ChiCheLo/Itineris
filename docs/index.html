Itineris 行程規劃 Web APP

這份文件記錄專案的計劃過程、功能規格、技術決策與開發紀錄，會隨開發進度持續更新。

1. 專案概述

目標

做一個以手機為主的旅遊行程規劃工具，取代目前用 iPhone 備忘錄排行程的方式。出發前用來準備機票、證件、入境資料、行李與行程；旅途中打開就能看到現在時間、機票時間和當下該做什麼。

目標使用者

  • 使用者本人與旅伴一起使用。
  • 旅行型態：國外自由行。目前預設的旅程是紐西蘭南島。

要解決的問題（使用者原話整理）

  • 用 iPhone 備忘錄排行程，沒有視覺化的介面。
  • 新增行程時沒辦法自動排序，全部都要手動調整，很麻煩。
  • 要找某個行程很花時間。

5. 技術架構

目前標準：可互動的純前端，沒有後端。資料存在使用者瀏覽器的 localStorage。因為要兩台手機看同一份行程（D-012），之後需要加入雲端同步，使用哪個服務待確認。
層面採用理由
前端原生 HTML / CSS / JavaScript，無框架、無建置流程直接雙擊 index.html 就能用，也能原封不動放上 GitHub Pages；P0 功能規模不需要框架
樣式CSS 變數（design tokens），支援淺色／深色模式所有間距、字級、圓角、顏色集中管理，依 ui-ux-pro-max 規範（第 7 節）
畫面切換hash 路由：#/ 首頁、#/trips 旅程列表、#/trip/:id/:day 旅程詳情不需要伺服器設定，重新整理或分享連結都會停在同一頁
資料儲存localStorage，key travelplan.v1MVP 不需要帳號；key 帶版本號方便之後資料遷移
拖曳排序自行以 Pointer Events 實作同時支援滑鼠與手機觸控，不需要外部套件
地圖（P1）Leaflet + OpenStreetMap（預定）免費、不需要 API 金鑰，可用 CDN 載入
部署GitHub Pages（預定）與 repo 整合、免費、純靜態檔案即可

若之後功能變多（共編、AI 建議、多頁狀態複雜），再評估改用 React + TypeScript + Vite。

6. 資料模型

正式版：Firestore 資料庫設計（草案，2026-10-13）

依 D-034～D-040。前端只透過一個資料存取模組（預定 js/data.js）讀寫 Firestore，畫面程式不直接碰資料庫，這就是前後端的分界。權限一律由 Firestore 安全規則在伺服器端檢查，不靠前端判斷。全程使用免費方案（Spark），不使用需要綁卡的 Cloud Functions（D-040）。
users/{uid}                         // Google 帳號基本資料（由 Google 提供）
  displayName, email, photoURL, createdAt

users/{uid}/personal/{tripId}       // 個人資料：只有本人能讀寫，旅伴看不到
  carried:  { TWD: number, NZD: number }   // 預算：帶了多少（D-025）
  shopping: ShopItem[]                     // 購買清單
  passport: CheckItem[]                    // 準備清單：護照（各自一份，D-037）
  packing:  CheckItem[]                    // 準備清單：攜帶物品（各自一份，D-075）
  visaDone: { [itemId]: true }             // 準備清單：簽證與入境資料「自己勾了哪些」（D-075）
  flights:  Flight[]                       // 機票：各自一份，只有自己看得到（D-077）
  fastTrack: { [flightId]: boolean }       // 機票上的快速通關勾選（各自勾，D-042）

trips/{tripId}                      // 共用：成員都能讀寫
  title, destination, startDate, endDate, currency
  ownerId                          // 建立者，只有他能刪除整趟旅程（D-039）
  members: uid[]                    // 成員名單
  memberProfiles: { [uid]: { name, photoURL } }
  invitedEmails: string[]           // 用 Gmail 邀請的旅伴（D-038）
  visa: { id, text }[]              // 準備清單：簽證與入境資料的項目（大家共用，勾選各自存，D-075）
  createdAt, updatedAt
  （舊欄位：trips.packing 是改版前共用的攜帶物品、personal.visa 是改版前各自的簽證清單，
    只用來搬移舊資料，新版不再寫入，D-075；trips.flights 是改版前共用的機票，
    只歸建立者，建立者下次存檔時搬到自己的 personal.flights 並從旅程上刪掉，D-077）

trips/{tripId}/days/{YYYY-MM-DD}    // 每天的行程分開存：兩人同時改不同天不會互相覆蓋
  date, activities: Activity[], updatedAt

Activity（在原型的欄位之外新增）
  split: { type: "all" }                     // 預設：除以全部成員人數（D-043）
       | { type: "some", uids: string[] }    // 部分人分攤：只除以這幾個人，也只算進他們的預算
       | { type: "self", uid: string }       // 個人開銷：全額算進這個人的預算

invites/{code}                      // 邀請連結（D-038）
  tripId, createdBy, expiresAt      // 有期限，例如 7 天

安全規則（Firestore Security Rules）重點

  • 沒登入什麼都不能讀寫。
  • users/{uid} 與底下的 personal：只有 uid 本人能讀寫。
  • trips/{tripId} 與 days：只有 members 裡的人能讀寫；只有 ownerId 能刪除旅程（先標記 deletedAt，D-071）、改 ownerId，以及把其他成員移出旅程（一次一位、不能移除自己，D-074）。
  • 加入旅程（邀請連結）：只能把「自己」加進 members，而且寫入時要附上有效、未過期、屬於這趟旅程的邀請碼。
  • 加入旅程（Gmail 邀請）：只有 Google 帳號 Email 已驗證、且在 invitedEmails 裡的本人，才能把自己加進 members。
  • 欄位型別與長度檢查（例如標題最多 60 字），避免塞入異常資料。

其他

  • 離線：開啟 Firestore 離線快取，沒網路時仍可查看與修改，連線後自動同步。
  • 舊資料：第一次登入時，把瀏覽器 localStorage 裡的旅程、預算、購買清單自動上傳到帳號（D-041）。
  • 同時編輯：同一天的同一個活動，兩人在同一刻修改時，後存的會覆蓋先存的。

原型（目前程式）使用的模型

以下是原型存在 localStorage 的模型，正式版會依上面的設計搬到 Firestore。
type Trip = {
  id: string;
  title: string;          // 例：東京五日遊
  destination: string;
  startDate: string;      // YYYY-MM-DD
  endDate: string;
  currency: string;       // 例：JPY
  travelers: number;      // 人數，預設 2；行程花費算進個人預算時除以人數
  days: Day[];
  flights: Flight[];      // 依出發時間排序
  prep: {                 // 準備清單，全部用勾選
    packing: CheckItem[]; // 攜帶物品
    passport: CheckItem[];
    visa: CheckItem[];    // 簽證與入境資料
  };
  createdAt: string;
  updatedAt: string;
};

type Flight = {
  id: string;
  airline: string;        // 例：紐西蘭航空
  flightNo: string;       // 例：NZ 78
  passenger: string;      // 與護照相同
  from: { code: string; city: string };  // 機場代碼 3 碼，例：TPE
  to:   { code: string; city: string };
  departDate: string;     // YYYY-MM-DD，當地時間
  departTime: string;     // HH:mm，當地時間
  arriveDate: string;
  arriveTime: string;
  boardingTime: string;
  cabin: string;          // 經濟艙／豪華經濟艙／商務艙／頭等艙
  terminal: string;
  gate: string;
  seat: string;
  bookingRef: string;     // 訂位代號
  transit?: "enter" | "airside";  // 抵達後轉機：需要入境／不用入境；沒有＝不是轉機（共用，D-065）
  // 快速通關的勾選是個人的，存在 users/{uid}/personal/{tripId}.fastTrack（D-042）
};

type CheckItem = {
  id: string;
  text: string;
  done: boolean;
};

// 個人資料：跟 trips 分開存在 state.personal[tripId]，
// 之後兩台手機同步時只同步 trips，預算與購買清單不會給旅伴看到（D-025）
type Personal = {
  carried: { [currency: string]: number };  // 帶了多少，例：{ TWD: 10000, NZD: 1500 }
  shopping: ShopItem[];
};

type ShopItem = {
  id: string;
  name: string;           // 品名
  price?: number;
  currency: string;       // TWD 或目的地貨幣
  done: boolean;          // 已買：勾了才算進「花了多少」
};

type Day = {
  date: string;           // YYYY-MM-DD
  activities: Activity[]; // 陣列順序即顯示順序
};

type Activity = {
  id: string;
  title: string;
  type: "sight" | "food" | "transport" | "lodging" | "other";
  startTime?: string;     // HH:mm
  endTime?: string;
  location?: {
    name: string;
    lat?: number;
    lng?: number;
  };
  cost?: number;
  note?: string;
};

7. 畫面規劃

畫面內容主要操作
首頁（打開 App 第一個畫面）大字現在時間與日期、旅程名稱與 Day 幾、下一班飛機（登機證）、當下行程（現在／接下來）點旅程或行程進入當天行程、「所有旅程」
旅程列表所有旅程卡片，顯示名稱、日期、天數新增旅程、進入旅程、返回首頁
新增／編輯旅程名稱、目的地、日期區間、幣別儲存、刪除
旅程詳情最上方機票區（登機證可左右滑動），接著日期分頁（Day 1、Day 2…），下方當天活動時間軸新增／編輯機票、新增活動、拖曳排序
機票編輯底部彈出面板：航空公司、航班、乘客、起訖機場、起降時間、登機時間、艙等、航廈、登機門、座位、訂位代號儲存、刪除
活動編輯底部彈出面板，填寫活動欄位儲存、刪除、移到其他天

RWD 版面

  • 手機（< 960px）：首頁由上到下：時間 → 旅程 → 下一班飛機 → 當下行程。
  • 桌機（≥ 960px）：首頁分兩欄，左邊是時間、旅程、當下行程，右邊是機票。
  • 登機證：依卡片本身寬度切換（container query）。寬度不到 560px 時是直式，存根在下方；560px 以上改成橫式，存根在右邊，跟實體登機證一樣。
  • 已在 375px、390px、768px、1280px 寬度和深色模式下截圖檢查。

主要使用流程

開啟 App → 新增旅程（填目的地與日期）→ 自動產生每日分頁 → 逐日新增活動 → 拖曳調整順序 → 旅途中用手機查看。
