TravelPlan 行程規劃 Web APP

這份文件記錄專案的計劃過程、功能規格、技術決策與開發紀錄，會隨開發進度持續更新。

Repo：ChiCheLo/TravelPlan_WebAPP 建立日期：2026-10-12 目前階段：依新規格開發中 開啟 App

1. 專案概述

目標

做一個以手機為主的旅遊行程規劃工具，取代目前用 iPhone 備忘錄排行程的方式。出發前用來準備機票、證件、入境資料、行李與行程；旅途中打開就能看到現在時間、機票時間和當下該做什麼。

目標使用者

  • 使用者本人與旅伴一起使用。
  • 旅行型態：國外自由行。目前預設的旅程是紐西蘭南島。

要解決的問題（使用者原話整理）

  • 用 iPhone 備忘錄排行程，沒有視覺化的介面。
  • 新增行程時沒辦法自動排序，全部都要手動調整，很麻煩。
  • 要找某個行程很花時間。

4. 非功能需求

  • 手機優先：以手機螢幕為主要設計對象，桌機版面延伸。
  • 介面語言：繁體中文。
  • 效能：首次載入在一般 4G 網路下 3 秒內可操作。
  • 離線可讀：旅途中沒網路時仍能查看已存的行程（P1，PWA）。
  • 隱私：MVP 不需要帳號，資料只存在使用者自己的裝置。

5. 技術架構

目前標準：可互動的純前端，沒有後端。資料存在使用者瀏覽器的 localStorage。因為要兩台手機看同一份行程（D-012），之後需要加入雲端同步，使用哪個服務待確認。
層面採用理由
前端原生 HTML / CSS / JavaScript，無框架、無建置流程直接雙擊 index.html 就能用，也能原封不動放上 GitHub Pages；P0 功能規模不需要框架
樣式CSS 變數（design tokens），支援淺色／深色模式所有間距、字級、圓角、顏色集中管理，依 ui-design-reference 規範
畫面切換hash 路由：#/ 首頁、#/trips 旅程列表、#/trip/:id/:day 旅程詳情不需要伺服器設定，重新整理或分享連結都會停在同一頁
資料儲存localStorage，key travelplan.v1MVP 不需要帳號；key 帶版本號方便之後資料遷移
拖曳排序自行以 Pointer Events 實作同時支援滑鼠與手機觸控，不需要外部套件
地圖（P1）Leaflet + OpenStreetMap（預定）免費、不需要 API 金鑰，可用 CDN 載入
部署GitHub Pages（預定）與 repo 整合、免費、純靜態檔案即可

若之後功能變多（共編、AI 建議、多頁狀態複雜），再評估改用 React + TypeScript + Vite。

目錄結構

TravelPlan_WebAPP/
├── index.html         # App 入口
├── css/
│   └── style.css      # design tokens 與所有樣式
├── js/
│   └── app.js         # 狀態、路由、畫面渲染、表單、拖曳排序
└── docs/
    └── index.html     # 本規劃文件

app.js 結構

  • Storage：load()／save()，讀寫 localStorage，失敗時以 toast 提示。
  • Routing：parseRoute() 解析網址 hash，render() 依路由重畫整個畫面。
  • Views：renderHome() 首頁、renderList() 旅程列表、renderTrip() 旅程詳情。
  • Home：homeTrip() 選出要顯示的旅程（旅途中 > 最近要出發 > 最近結束），activityNowNext() 找出現在與接下來的活動，startClock() 每分鐘重畫。
  • 機票：boardingPass() 產生登機證樣式的卡片，openFlightForm() 新增／編輯機票。
  • Sheet：openSheet() 共用的底部面板，旅程與活動表單都用它。
  • Undo：snapshot() 在刪除前保存資料快照，toast 上的「復原」可還原。

6. 資料模型（草案）

以下是目前程式使用的模型，已加入機票（Flight）。證件、物品清單、預算等資料做到該功能時再補上。
type Trip = {
  id: string;
  title: string;          // 例：東京五日遊
  destination: string;
  startDate: string;      // YYYY-MM-DD
  endDate: string;
  currency: string;       // 例：JPY
  days: Day[];
  flights: Flight[];      // 依出發時間排序
  createdAt: string;
  updatedAt: string;
};

type Flight = {
  id: string;
  airline: string;        // 例：紐西蘭航空
  flightNo: string;       // 例：NZ 78
  passenger: string;      // 與護照相同
  from: { code: string; city: string };  // 機場代碼 3 碼，例：TPE
  to:   { code: string; city: string };
  departDate: string;     // YYYY-MM-DD，當地時間
  departTime: string;     // HH:mm，當地時間
  arriveDate: string;
  arriveTime: string;
  boardingTime: string;
  cabin: string;          // 經濟艙／豪華經濟艙／商務艙／頭等艙
  terminal: string;
  gate: string;
  seat: string;
  bookingRef: string;     // 訂位代號
};

type Day = {
  date: string;           // YYYY-MM-DD
  activities: Activity[]; // 陣列順序即顯示順序
};

type Activity = {
  id: string;
  title: string;
  type: "sight" | "food" | "transport" | "lodging" | "other";
  startTime?: string;     // HH:mm
  endTime?: string;
  location?: {
    name: string;
    lat?: number;
    lng?: number;
  };
  cost?: number;
  note?: string;
};

7. 畫面規劃

畫面內容主要操作
首頁（打開 App 第一個畫面）大字現在時間與日期、旅程名稱與 Day 幾、下一班飛機（登機證）、當下行程（現在／接下來）點旅程或行程進入當天行程、「所有旅程」
旅程列表所有旅程卡片，顯示名稱、日期、天數新增旅程、進入旅程、返回首頁
新增／編輯旅程名稱、目的地、日期區間、幣別儲存、刪除
旅程詳情最上方機票區（登機證可左右滑動），接著日期分頁（Day 1、Day 2…），下方當天活動時間軸新增／編輯機票、新增活動、拖曳排序
機票編輯底部彈出面板：航空公司、航班、乘客、起訖機場、起降時間、登機時間、艙等、航廈、登機門、座位、訂位代號儲存、刪除
活動編輯底部彈出面板，填寫活動欄位儲存、刪除、移到其他天

RWD 版面

  • 手機（< 960px）：首頁由上到下：時間 → 旅程 → 下一班飛機 → 當下行程。
  • 桌機（≥ 960px）：首頁分兩欄，左邊是時間、旅程、當下行程，右邊是機票。
  • 登機證：依卡片本身寬度切換（container query）。寬度不到 560px 時是直式，存根在下方；560px 以上改成橫式，存根在右邊，跟實體登機證一樣。
  • 已在 375px、390px、768px、1280px 寬度和深色模式下截圖檢查。

主要使用流程

開啟 App → 新增旅程（填目的地與日期）→ 自動產生每日分頁 → 逐日新增活動 → 拖曳調整順序 → 旅途中用手機查看。

第一次使用時列表是空的，可以點「看範例行程」載入一份東京四日遊的範例資料。

設計規範（依 ui-design-reference）

所有畫面設計都先參考 ui-design-reference，再動手實作。

項目規範
風格原型原生 iOS（Things 3 類）為主：Large Title、底部面板、清單；旅程卡片比例參考圖片主導的市集類 App
間距4/8 格線：4、8、12、16、24、32、48；手機左右邊界 16
字級12 / 14 / 16 / 18 / 20 / 30；字重只用 400 / 600 / 700；金額與時間用等寬數字
圓角6 / 8 / 12 / 16 / 24 / full；底部面板頂部 24
色彩暖灰中性色 + 單一綠色主色（只用在主要按鈕、選取狀態）；活動類型各有一個語意色
深色模式背景 #121211，用表面亮度分層，不靠陰影；邊框為白色 8% 透明度
按鈕每個畫面只有一個主要按鈕；點擊區至少 44×44；有 hover / focus / active 狀態
圖示統一使用 Lucide 線條風格 SVG，不用 emoji
表單標籤在欄位上方；手機欄位高 48；錯誤訊息顯示在表單內，說明怎麼修正
刪除直接刪除並顯示可「復原」的 toast（5 秒），不跳確認對話框
動態底部面板 360ms、ease-out-expo；只動 transform 與 opacity；尊重「減少動態效果」設定
狀態旅程列表、每日行程都有空狀態（圖示 + 說明 + 行動）
